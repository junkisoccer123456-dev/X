# 年齢別キャリアステップ型

- 構成（種別）: 本文 → リプ1 → リプ2
- 実績: imai で伸びたポスト

## 概要
「〇〇としての理想的なキャリアステップ（新卒〜30歳）」を、【22歳（新卒）】〜【30歳】の1歳ごとに、担当する仕事・身につく視点・年収で示す。本文は22〜24歳で「25歳〜」と止め、リプ1で25〜27歳、「28歳〜」で止め、リプ2で28〜30歳と締めの考察。

## ルール
- 本文: 1行目「〇〇としての理想的なキャリアステップ（新卒〜30歳）」→【22歳（新卒）】【23歳】【24歳】→「25歳〜」
- 各年齢: 立場・任される仕事（2文）→ その年に身につく視点や考え始めること（1〜2文）→「年収は【　】万円。」
- リプ1: 【25歳】【26歳】【27歳】（多くの場合25歳前後で転職が入る）→「28歳〜」
- リプ2: 【28歳】【29歳】【30歳】→ 締め「〇〇で年収を大きく伸ばす人は、『〇〇な人』ではなく『〇〇な人』へ進化しています。」→「なお、これは私が20代の転職支援をしてきた中で見てきた、伸びた方に多い流れを一つのモデルにしたものです。全員がこの通りに進むわけではありません。」
- **年収は根拠のない数字にしないため【　】の空欄にする**（ユーザーが実データや相場で埋める）。

## お手本

### 本文
```
エンジニアとしての理想的なキャリアステップ（新卒〜30歳）

【22歳（新卒）】
SIerまたは受託開発企業へ新卒入社。
詳細設計、コーディング、単体テスト、仕様書作成、障害対応など下流工程を担当。先輩のレビューを受けながら、動くコードを書く力とチーム開発のルールを体に入れる期間。エンジニアとしての土台を作る時期。年収は350万円。

【23歳】
基本設計や結合テストにも関与するようになる。
要件を満たすだけでなく、保守性、可読性、処理速度を意識した実装へ。なぜこの技術を選んだのかを自分の言葉で説明できるようになり始める。年収は400万円。

【24歳】
小規模案件のリーダーを任される。
要件定義への同席、工数見積、進捗管理、後輩指導を経験。一方で、指示された仕様を作るだけではなく、その機能がなぜ必要なのかという事業側の議論に入りたいと考え始める。年収は460万円。

25歳〜
```

### リプ1
```
【25歳】
開発経験を評価され、自社サービスを持つIT企業へ転職。モダンな技術スタック、CI/CD、アジャイル開発を経験する。受託では触れられなかった「作った後の改善サイクル」を初めて回すことになる。年収は550万円。

【26歳】
バックエンドを中心に、アーキテクチャ設計、DB設計、パフォーマンス改善、クラウドインフラ構築まで担当領域を拡大。技術的な意思決定が事業指標に直結する感覚を持ち始める。年収は620万円。

【27歳】
テックリードとして、技術選定、レビュー基準の策定、開発生産性の改善、採用の技術面接を担当。個人の実装力ではなく、チームの出力を上げる立場へ移行する。年収は700万円に到達。

28歳〜
```

### リプ2
```
【28歳】
事業会社の開発組織で、新規プロダクトの立ち上げまたは基盤チームへ。技術的負債の返済、SRE、セキュリティ設計など、事業を止めないための技術を担う。転職市場でも高い評価を受ける状態になる。年収は800万円。

【29歳】
エンジニアリングマネージャーとして、採用、育成、評価制度、開発ロードマップの策定まで担当。技術と経営の翻訳者として、経営会議に出る機会が増える。年収は880万円。

【30歳】
VPoE候補、あるいは特定領域のスペシャリストとして、技術戦略そのものを担う立場へ。設計、組織、採用、事業判断まで一気通貫で語れることで、市場価値の高いエンジニアになる。年収は1,000万円に到達。

エンジニアで年収を大きく伸ばす人は、「速く正確に作れる人」ではなく、「作るべきかどうかを判断できる人」へ進化しています。なお、これは私が20代の転職を3,000名支援してきた中で、上位の伸び方をした方に共通するルートです。全員がこの通りに進むわけではありません。
```
