# チェックリスト→理由→本質型

- 構成（種別）: 本文 → リプ1 → リプ2

## 概要
本文で「この記載（言動）があったら一度立ち止まってください」と、見落としがちな危険サインを7つ並べ、「なぜ危険なのか、続きに書きます↓」でリプへ。リプ1で項目ごとの理由を「→」で示し、「1つだけなら危険とは言えない、3つ以上重なったら疑う」と過度な断定を避ける。リプ2で本質（何を見るべきか）と、同じ構造の別サインを示して締める。

## ルール
- 本文: 「〇〇で、この〇〇があったら一度立ち止まってください。」→「・」で7項目（具体的な文言や数値の例）→「なぜこれが危険なのか、続きに書きます↓」
- リプ1: 「理由はそれぞれ違います。」→「・項目 → 理由」を5つ →「なお、1つ当てはまるだけで危険とは言えません。3つ以上重なったときに、〇〇そのものを疑ってください↓」
- リプ2: 「〇〇は、〇〇が見せたいものだけを書いた”プレゼン資料”です」のような本質の一言 → 何を見るべきか3点 → 同じ構造の別サイン2つ。
- 危険サインは accounts のナレッジ（ブラック企業の見分け方など）に沿う。

## お手本

### 本文
```
未経験エンジニアの求人票で、この記載があったら一度立ち止まってください。

・みなし残業45時間以上
・勤務地「プロジェクトによる」
・年収250万〜800万
・必須要件が「PC基本操作」のみ
・「学歴不問、人柄重視」
・配属先は入社後に決定
・「転勤の有無」の記載自体がない

なぜこれが危険なのか、続きに書きます↓
```

### リプ1
```
理由はそれぞれ違います。

・みなし残業が多い → その時間働く前提で設計されている
・勤務地がぼかされている → 自社ではない場所で働く可能性が高い
・年収幅が異常に広い → 上限は別ポジションの数字であることが多い
・必須要件が簡素 → 誰でも通す前提の採用設計になっている
・記載がない項目 → 書いていないのではなく、確定していない

なお、1つ当てはまるだけで危険とは言えません。
3つ以上重なったときに、採用の設計そのものを疑ってください↓
```

### リプ2
```
求人票は、企業が求職者に見せたいものだけを書いた”プレゼン資料”です書いてあることより、書いていないことを見てください。配属先、勤務地、年収の内訳。この3つが曖昧なまま選考が進む場合、内定後に条件が変わる可能性があります。
内定を受けた後に条件面談を依頼して、実施しない企業。承諾期限が数日しかない企業。この2つも同じ構造です。
```
