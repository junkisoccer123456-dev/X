# /x-post — 構文を指定してX投稿を生成する

## 手順

### 1. 引数を読む
- `$ARGUMENTS` の最初の語がアカウント名。残りに構文の名前や本数（「20本」など）が入っていれば使う。本数の指定がなければ **1構文あたり10本**。
- `accounts/<アカウント名>.md` を読む。ない場合は、`accounts/` にある登録済みアカウントの一覧を見せ、「`/x-account <アカウント名>` で先に登録してください」と伝えて止まる。

### 2. 構文を決める
構文は「投稿の型」です。`structures/` に保存済みの構文があります（ファイル名＝構文名）。

- **引数やメッセージに構文名がある** → `structures/` から一致するもの（表記ゆれは近いものを選ぶ）を読む。
- **ユーザーが構文を文章や参考ポストで貼ってきた** → 内容を分析して、次の形の構文定義を作る:
  - 構文名（「〇〇→〇〇型」の形。ユーザーが名前を付けていればそれを使う）
  - 構成（種別）: 1セットが「本文」だけか、「本文 → リプ1 → リプ2 …」か、「パターンA/B/C」か
  - 各パートの型（1行目のフック、箇条書きの形、締めの一言、次のリプへのつなぎ方など）
  - お手本（貼られた参考ポスト）

  作った定義は `structures/<構文名>.md` に保存する（既存ファイルと同じ見出し構成: 構成 / 概要 / ルール / お手本）。次回から名前だけで使える。
- **何も指定がない** → 保存済みの構文名を一覧で見せて、「どの構文で作りますか？ 新しい構文なら型や参考ポストを貼ってください」と聞いて待つ。
- 複数の構文を指定された場合（例:「7構文」「NG連打とABC3」）は、構文ごとに指定本数ずつ作る。

### 3. 過去のテーマを集める（重複を避けるため）
- Google Drive のツールが使える場合: タイトルに `X投稿_<アカウント名>_` を含むスプレッドシートを検索し、新しいもの最大10件の「テーマ」列を読む。
- `output/` に同じアカウントのCSVがあれば、それのテーマ列も読む。
- どちらも使えなければ、この手順は飛ばす。

### 4. 伸びるテーマを選ぶ
1構文につき指定本数ぶんのテーマを選ぶ。次の条件をできるだけ多く満たすものを優先する。
- ターゲット読者の悩みのど真ん中にある（「自分のことだ」と思える）
- 保存したくなる具体性がある（リスト、手順、NG例と言い換え、チェック項目）
- 発信者の立場・経歴だから言える（採用側の本音、現場の一次情報）
- その構文の型と相性がよい（リスト型ならリストにしやすいテーマ、NG→OK型なら失敗例が多いテーマ）
- 過去のテーマや、今回作る他の投稿と重ならない

### 5. 投稿を書く
- アカウントに「出力ルール」の見出しがあれば、**構文より優先して**従う。
  - 「1テーマにつきパターンA/B/Cの3パターン」とある場合: テーマごとに、その構文の型でA/B/Cの3本を作る（10テーマなら30本）。種別は構文の種別の前に付ける（例: 本文だけの構文なら「パターンA」、本文→リプの構文なら「パターンA・本文」「パターンA・リプ1」）。
  - 文字数の指定（例: 140文字以内、記事構文は3000文字以上）は、それに合わせる。
- 構文の**構成とルールを厳守**する。お手本の形式・温度感をまねるが、内容はコピーしない。
- アカウントの口調（一人称、語尾、口語の頻度）、CTA、ルールに従う。
- 経歴・実績は `accounts/` に書いてある事実だけを使う。数値・社名・実績を創作しない。確認できない事実は【　】の空欄にする。
- 実在の企業名を並べる場合は、アカウントのルールにある注意書きを添える。
- スマホで読みやすいよう、改行と空行を入れる。

### 6. 出す前にセルフチェック
すべての投稿について確認し、問題があれば直してから出す。
- [ ] 種別の並びが構文の構成と一致している（リプの本数が合っている）
- [ ] 1行目がフックになっている
- [ ] 口調がアカウント設定どおり（一人称・語尾・口語を使いすぎていない）
- [ ] 数値や実績を創作していない
- [ ] テーマが過去・今回の他の投稿と重なっていない
- [ ] 文字数がアカウント設定どおり（140文字以内の設定なら各パーツが280（Xのカウント）以内、記事構文で3000文字以上の設定ならそれ以上）
- [ ] アカウントの禁止事項（ターゲット外の読者、テンプレ表現、宣伝感など）に触れていない

### 7. 出力する
1. **チャットに全文を表示する。** テーマごとに番号を振り、種別（本文／リプ1…）ごとに分けて見せる。複数構文のときは構文ごとに見出しを付ける。
   合計が20本を超える場合は、構文ごとのテーマ一覧と各構文1本ぶんの全文だけを見せ、残りの全文はスプレッドシートで確認してもらう（チャットが長くなりすぎるため）。
   ユーザーが「スプシに反映でOK」などと言った場合は、全文の表示は省き、テーマ一覧とスプレッドシートのURLだけを伝える。
2. **CSVを作る。** 次の形のJSONを一時ファイル（スクラッチパッド）に書き、スクリプトで変換する。
   ```json
   {"account": "<アカウント名>", "date": "<今日 YYYY-MM-DD>",
    "posts": [{"structure": "<構文名>", "theme": "<テーマ>",
               "parts": [{"kind": "本文", "text": "..."}, {"kind": "リプ1", "text": "..."}]}]}
   ```
   ```bash
   python3 scripts/to_csv.py <JSONのパス> --out-dir output
   ```
   1投稿の文字数上限がある設定（無料アカウント、140文字以内など）なら `--limit 280` を付ける（記事構文のときは付けない）。複数構文をまとめたときの名前は自動で「N構文M本」になる。
   標準出力の1行目がシート名、2行目がCSVのパス。
3. **Googleスプレッドシートに保存する。** Google Drive のツール（`create_file`）が使える場合、タイトル＝シート名、`textContent`＝CSVの中身（先頭のBOMは除く）、`contentMimeType`＝`text/csv` で作成する（自動でスプレッドシートに変換される）。作成したURLを伝える。
   使えない場合は、CSVのパスを伝え、Google Drive のコネクタを接続すれば自動保存できることを一言添える。

### 列の形式（既存の管理シートと同じ）
`No, テーマ, 種別, テキスト, date, account, structure, status, post_url, impressions, likes, bookmarks, reposts, profile_visits, note`
- 1パーツ＝1行。同じ投稿の本文とリプは同じ No。No は構文ごとに1から振る。
- status は `draft`。post_url から profile_visits は投稿後に手で記入する列なので空欄。
